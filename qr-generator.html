Choosing an error correction level

Every QR code has a built-in error-correction level — Low, Medium, Quartile or High — that determines how much of the code can be damaged, dirty, or obscured before it stops scanning. Higher correction levels add redundant data, which makes the code denser (more modules) for the same content, but means it will still scan even if part of it is torn, smudged, or has a small logo placed over the center.

For most everyday uses — a link on a flyer, a WiFi card, a menu on a laminated table tent — Medium (15%) is a reasonable default. If the code is going somewhere it might get scuffed, printed small, or partially covered (a sticker on outdoor equipment, a code stamped near a product's rough edge), step up to Quartile or High. If you're only ever displaying the code on a clean screen and space is at a premium, Low (7%) keeps the module count as small as possible.

Picking the right content type

The tool above supports five payload types, each of which produces a different underlying data format inside the QR code:

  • Link: encodes a plain URL. This is the most common use — packaging, posters, and business cards that point to a webpage.
  • Text: encodes arbitrary plain text with no special formatting. Useful for instructions, a short message, or a serial/reference number you want a phone to be able to read and copy.
  • WiFi: encodes network name, password and security type in the standard WIFI: format that iOS and Android both recognize automatically, letting a guest join your network with a single scan instead of typing a password on a small keyboard.
  • Email: pre-fills a "mailto:" link with a recipient, subject and body, so scanning opens the user's mail app with a message already drafted.
  • Contact Card: encodes a vCard, which most phones offer to save directly into the address book rather than just opening a link — the standard choice for a digital business card.

Sizing and contrast tips for printed QR codes

A QR code needs a certain minimum physical size to scan reliably, and that minimum scales with how much data it holds — a code encoding a full vCard needs to be printed larger than one encoding a short URL, because it has more modules packed into the same shape. As a rough starting point, aim for at least 2 cm (about 0.8 in) per side for a simple URL viewed from a normal reading distance, and size up for anything with more content or that will be scanned from farther away (like a billboard or a shop window).

Keep a clear quiet zone — blank space — around the code, and stick to strong contrast between the foreground and background colors. Light-on-light or two similarly-toned colors can look fine on a monitor but fail to scan once printed, especially on lower-end inkjet or thermal printers.
